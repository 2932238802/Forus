# 15 · 主题配色变量化（可选）

- 优先级：P3
- 类型：视觉 / 重构
- 依赖：14
- 影响文件：`assets/css/main.css`、`tailwind.config.ts`、几乎所有页面与组件
- 状态：✅ 已执行（2026-11-14）

## 问题

目前只有背景、`accent-*`、`text-gradient` 跟随主题变量；按钮、标签、状态色仍大量写死：

- 蓝色系：`text-sky-300`、`bg-sky-500`、`border-sky-400`
- 粉色/错误：`text-rose-*`、`bg-rose-500`
- 成功：`text-emerald-*`、`bg-emerald-500`

结果：切到樱花主题时，背景变粉，但主要按钮和强调仍是蓝色，视觉不统一。

## 方案

### 1. 定义语义变量

`main.css` 每套主题补充：

```css
:root, [data-theme='star'] {
  --accent: #38bdf8;
  --accent-2: #7dd3fc;
  --accent-rgb: 56, 189, 248;
  --positive: #34d399;
  --positive-rgb: 52, 211, 153;
  --negative: #fb7185;
  --negative-rgb: 251, 113, 133;
  --warning: #fbbf24;
  --warning-rgb: 251, 191, 36;
}

[data-theme='sakura'] {
  --accent: #fb7faf;
  --accent-2: #fdb8d2;
  --accent-rgb: 251, 127, 175;
  --positive: #4ade80;
  --positive-rgb: 74, 222, 128;
  --negative: #f472b6; /* 樱花主题下用更柔和的粉 */
  --negative-rgb: 244, 114, 182;
  --warning: #fbbf24;
  --warning-rgb: 251, 191, 36;
}
```

### 2. 新增语义工具类

- `.accent-text` / `.accent-bg` / `.accent-border`（已有前两个）
- `.positive-text` / `.positive-bg` / `.positive-border`
- `.negative-text` / `.negative-bg` / `.negative-border`
- `.warning-*`（按需）

或者扩展 `tailwind.config.ts`：

```ts
colors: {
  accent: 'rgb(var(--accent-rgb) / <alpha-value>)',
  positive: 'rgb(var(--positive-rgb) / <alpha-value>)',
  negative: 'rgb(var(--negative-rgb) / <alpha-value>)',
}
```

之后可使用 `text-accent`、`bg-negative/10` 等 Tailwind 语法。推荐这种方式，改动更自然。

### 3. 逐页替换

按页面分批：

1. 全局组件：`NavBar`、`ThemeSwitcher`、`FoldCard`、`CurtainIntro`
2. 首页：`TogetherCard`、`NoteWall`、`MediaWall`、`TimelineCompact`
3. 功能页：`memo`、`goals`、`likes`、`adore`、`dislikes`、`letters`、`push`
4. 隐藏页：`calendar`、`CatChat`、`PokeAlert`、`Celebration`

替换原则：

- 主色 → `accent`
- 成功 / 已完成 → `positive`
- 错误 / 删除 / 不喜欢 → `negative`
- 警告 / 生日 → `warning`
- 中性文字、边框继续用 `slate` / `white/10`
- 保留每个页面已有的语义（例如「喜欢」用 positive、「不喜欢」用 negative）

### 4. 对比度

两套主题下检查：

- 文字与背景对比度；
- 半透明背景（`bg-accent/10`）是否可读；
- 按钮 hover / active 状态。

## 验收标准

- [ ] 两套主题下主要按钮、标签、状态色都跟随主题。
- [ ] 不再出现「樱花主题 + 蓝色主按钮」的割裂感。
- [ ] 喜欢/不喜欢、成功/错误的语义色在切换主题后仍然可区分。
- [ ] 移动端与桌面端截图对比通过。
- [ ] `npm run build` / `npm run typecheck` 通过。

## 风险与回滚

- 改动面覆盖全部 UI，视觉回归风险最高；建议单独分支、逐页截图。
- 不建议与功能性修复混在同一个提交。
- 回滚：保留旧的 Tailwind 类或 `git revert`。
- 如果只想先解决最扎眼的部分，可只替换按钮与标题，作为第一阶段。
