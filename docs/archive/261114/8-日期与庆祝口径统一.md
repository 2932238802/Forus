# 08 · 日期与庆祝口径统一

- 优先级：P2
- 类型：正确性 / 体验
- 依赖：无
- 影响文件：`utils/date.ts`、新增 `composables/useToday.ts`、`components/TogetherCard.vue`、`layouts/default.vue`、`pages/calendar.vue`、`server/api/cat.post.ts`

## 问题

1. `togetherDuration().days` 从 0 开始（起始日当天显示「0 天」），而 `daysSince()` 含今天（起始日当天为 1），整百天判断用的也是后者。两个「在一起 N 天」差 1。
2. `TogetherCard.vue:10`、`layouts/default.vue:8` 的 `todayCelebration()` 只在初始化时执行一次；页面跨过午夜不会更新。`computed` 没有响应式依赖，实际也只算一次。
3. `pages/calendar.vue:18-19` 的 `today` / `todayStr` 是 setup 时的静态值，跨午夜后「今天」高亮和天气区不会刷新。
4. SSR 与客户端时区不同时，日期相关渲染可能产生 hydration 警告。

## 方案

### 1. 统一天数口径

`utils/date.ts`：

- `togetherDuration` 的 `days` 改为 `Math.floor(diff / 86400) + 1`，与 `daysSince` 一致（起始日 = 第 1 天）。
- 为 `daysSince`、`daysUntil`、`togetherDuration`、`nextAnniversary` 增加可选 `now: Date = new Date()` 参数，方便测试和响应式调用。
- 更新函数注释，明确「含今天」。

### 2. 新增 `useToday`

`composables/useToday.ts`：

```ts
import { ref, onMounted, onUnmounted } from 'vue'

const today = ref<Date | null>(null)
let timer: ReturnType<typeof setInterval> | null = null
let users = 0

export function useToday() {
  onMounted(() => {
    today.value = new Date()
    users++
    if (!timer) timer = setInterval(() => (today.value = new Date()), 60_000)
  })
  onUnmounted(() => {
    users--
    if (users <= 0 && timer) {
      clearInterval(timer)
      timer = null
      today.value = null
    }
  })
  return { today }
}
```

- `today` 在挂载前为 `null`，避免 SSR/客户端时间差导致 hydration 不一致。
- 每分钟刷新一次，跨午夜后最多 1 分钟更新。

### 3. 组件接入

`components/TogetherCard.vue`

- `const { today } = useToday()`。
- `celebration = computed(() => today.value ? todayCelebration(today.value) : null)`。
- `anniv = computed(() => today.value ? nextAnniversary(siteConfig.startDate, today.value) : null)`，模板加 `v-if="anniv"`。
- 每秒跳动的 `dur` 不变，`days` 现在是第 1 天起算。

`layouts/default.vue`

- `const { today } = useToday()`；
  `isNpyBirthday = computed(() => !!today.value && todayCelebration(today.value)?.kind === 'birthday-npy')`。

`pages/calendar.vue`

- 用 `useToday()` 获取响应式「今天」。
- 初始选中日仍用挂载时的 `new Date()`，避免 `selected` 为空导致农历解析失败。
- `todayStr`、`isSelToday` 改为 computed；`goToday()` 使用 `today.value || new Date()`。
- 跨午夜后「今天」高亮与天气区自动切换到新的日期。

`server/api/cat.post.ts`

- 在一起天数改用 `daysSince(siteConfig.startDate)`，与前端口径一致。
- 仍使用北京时间判断深夜/凌晨。

## 验收标准

- [ ] 起始日当天，首页显示「在一起 1 天」；整百天彩蛋与显示天数一致。
- [ ] 修改系统时间跨过午夜（或 mock `useToday`），首页徽章、生日氛围、日历「今天」在 1 分钟内更新。
- [ ] 首屏水合无「Hydration node mismatch」警告。
- [ ] 日历默认选中今天，农历/黄历/天气正常。
- [ ] `docs/database.md` 等文档中涉及天数的描述无需修改。

## 风险与回滚

- 天数从 0 起算改为 1 起算，属于显示口径变化；如有历史截图对比会看到 +1。
- 回滚：恢复 `togetherDuration` 的 `+1` 与 `useToday` 接入。
