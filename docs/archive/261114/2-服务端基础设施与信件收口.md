# 02 · 服务端基础设施与信件收口

- 优先级：P0（敏感数据保护）
- 类型：安全 / 架构
- 依赖：01
- 影响文件：`nuxt.config.ts`、`.env.example`、`server/utils/*`、`server/api/letters/*`、`composables/useLetters.ts`、`pages/letters.vue`、`supabase/letters.sql`

## 问题

「给未来的信」目前由前端直连 Supabase 读写。由于 `letters` 表的 RLS 是 `anon` 全量读写，**任何拿到 anon key 的人都能读取所有信件内容**，前端「到期才能拆」的判断形同虚设。这是当前最敏感的数据暴露面。

## 方案

引入服务端管理客户端，把 `letters` 的读写全部收口到 Nitro。其余需要实时同步的表（notes / media / memos / likes…）保持现有直连模式，避免牺牲 Realtime。

### 1. 新增环境变量

```bash
# 仅服务端可见，绝不能放进 runtimeConfig.public
SUPABASE_SERVICE_ROLE_KEY=eyJ...
```

`nuxt.config.ts` 的 `runtimeConfig` 增加：

```ts
supabaseServiceKey: process.env.SUPABASE_SERVICE_ROLE_KEY || '',
```

同步更新 `.env.example` 和部署文档。

### 2. 新增服务端工具

`server/utils/supabase-admin.ts`

- `adminRest<T>(path, options)`：用 `config.public.supabase.url` + `service_role` key 调 PostgREST。
- 未配置 key 时抛 500，提示「缺少 SUPABASE_SERVICE_ROLE_KEY」。
- 统一带 `Prefer: return=representation`。

`server/utils/require-unlock.ts`

- `requireUnlocked(event)`：校验 `forus_token`，失败抛 401。
- `parseIdentity(value)`：只接受 `'you' | 'npy'`，否则抛 400。
- `partnerOf(identity)`：返回对方身份。
- 身份由客户端声明，服务端只校验格式；两个人都知道暗号，因此这属于「已解锁设备」内的可信声明，不构成额外权限。

### 3. 新增信件接口

| 方法 | 路径 | 行为 |
|------|------|------|
| GET | `/api/letters?identity=you` | 只返回 `who_from = identity OR who_to = identity` 的信；按 `unlock_date` 升序 |
| GET | `/api/letters/:id?identity=you` | 取单封完整内容；发件人始终可读，收件人仅在到期后可读，否则 403 |
| POST | `/api/letters` | body `{ identity, title, content, unlockDate }`；`who_from = identity`，`who_to = partner` |
| PATCH | `/api/letters/:id` | body `{ identity, title?, content?, unlockDate? }`；仅发件人、且信件尚未到期时可改 |
| DELETE | `/api/letters/:id?identity=you` | 仅发件人可删 |

规则：

- 列表接口对「收件人 + 未到期」的信返回 `content: null`、`locked: true`，只给标题和日期。
- 所有接口先 `requireUnlocked(event)`。
- 时间比较统一用服务端当天（`YYYY-MM-DD`），到期日当天即可读。
- 标题 ≤ 40、内容 1–5000 字符、`unlockDate` 为合法 `YYYY-MM-DD` 且不早于今天。

### 4. 前端改造

`composables/useLetters.ts`

- 删除 `useSupabaseClient`、Realtime 频道、`onUnmounted`。
- 增加 `fetchAll()`：`$fetch('/api/letters', { query: { identity } })`。
- `watch(identityKey, v => v && fetchAll())`，保证页面 `loadIdentity()` 之后自动拉取。
- `sendLetter(identity, title, content, unlockDate)`；`updateLetter(id, identity, patch)`；`removeLetter(id, identity)`。
- 新增 `openLetter(id)`：调用 `GET /api/letters/:id`，把完整内容合并进本地列表。
- `Letter` 增加可选 `locked?: boolean`。

`pages/letters.vue`

- 适配新的函数签名。
- `tryOpen` 改为 async：可读但本地 `content` 为空时，先 `openLetter(id)` 再展开。
- 删除信件时传入 `me`。
- 错误提示交给编号 09 统一处理。

### 5. 数据库迁移

新增 `supabase/upgrade-letters-service.sql`：

```sql
alter table public.letters enable row level security;

-- 移除匿名读写策略，之后只有 service_role（服务端）可访问
drop policy if exists "anon all letters" on public.letters;
revoke select, insert, update, delete on public.letters from anon;

-- 信件不再实时广播
do $$
begin
  alter publication supabase_realtime drop table public.letters;
exception
  when undefined_object then null;
end $$;
```

同时修改 `supabase/letters.sql`（全新安装用）：不再创建 `anon all letters` 策略，只保留建表、索引、RLS。已有环境执行上面的升级脚本。

## 验收标准

- [ ] 用 anon key 直接请求 `GET /rest/v1/letters` 返回空数组或权限错误。
- [ ] 已解锁设备通过 `/api/letters` 能看待自己发出和收到的信。
- [ ] 未到期信件：收件人列表只看到标题/日期，`content` 为 null；直接请求单封返回 403。
- [ ] 到期当天收件人可展开阅读。
- [ ] 发件人可新增 / 修改（未到期）/ 删除；收件人不能改别人的信。
- [ ] 未解锁或 Cookie 被清除时，四个接口均返回 401。
- [ ] 页面刷新后信件列表正常，不再依赖 Realtime。

## 风险与回滚

- 需要新增 `SUPABASE_SERVICE_ROLE_KEY`，该 key 权限极高，只能放在服务端环境变量。
- 信件失去实时同步；对「写给未来」功能无实际影响。
- 回滚：恢复 `anon all letters` 策略，前端 `useLetters` 切回 Supabase client。
- 本方案不覆盖 `media` 的公开读；Storage 写权限在编号 04 处理。
