# 09 · 写操作错误反馈与时间线确认

- 优先级：P2
- 类型：健壮性 / 体验
- 依赖：无
- 影响文件：多数 `composables/*.ts` 与 `pages/*.vue`、新增 `utils/errors.ts`

## 问题

1. 大部分写操作不检查 Supabase 返回的 `error`：`useNotes.addText`、`useGoals.addGoal`、`useMemo.addMemo`、`usePushbacks.addPushback` 等。断网、RLS 变更或字段错误时，用户看不到任何提示，输入内容也已经被清空。
2. 部分页面调用 composable 时不 `await`（如 `pages/memo.vue` 的 `submitMemo`），错误更无法捕获。
3. `components/TimelineCompact.vue:75` 删除节点没有二次确认，容易误删。

## 方案

### 1. 统一错误文案工具

新增 `utils/errors.ts`：

```ts
export function errorMessage(err: unknown): string {
  if (err && typeof err === 'object' && 'message' in err) {
    return String((err as { message: unknown }).message)
  }
  return String(err ?? '未知错误')
}

export function notifyError(action: string, err: unknown) {
  alert(`${action}失败：${errorMessage(err)}`)
}
```

本批次沿用现有 `alert()` 风格，不引入新的 Toast 系统；后续可平滑替换。

### 2. composable 统一抛错

所有写操作检查 `error`，有错就 `throw new Error(error.message)`：

- `useNotes`：`addText`、`addImage`、`removeNote`
- `useGoals`：`addGoal`、`toggleGoal`、`removeGoal`
- `useMemo`：`addMemo`、`toggleMemo`、`updateMemoText`、`removeMemo`
- `useLikes`：`addLike`、`removeLike`（`updateLike` 已抛）
- `useMilestones`：`addMilestone`、`updateMilestone`、`removeMilestone`
- `usePushbacks`：`addPushback`、`updatePushback`、`removePushback`
- `useCalendar`：`setMark` 的删除分支
- `useAdores`：`removeAdore`
- `useMemoComments`：`removeComment`
- `useLetters` / `useCat`：在编号 02 / 03 中一并处理
- `useMedia`：已有抛错，保持

只读/实时逻辑不变。

### 3. 页面统一 `await` + `try/catch`

逐个页面把提交/切换/删除改为 async，并捕获：

- `components/NoteWall.vue`：`sendText`、`confirmRemove`（删除失败提示）
- `components/TimelineCompact.vue`：`save`、新增 `confirmRemove`
- `pages/goals.vue`：`submit`、`toggleGoal`、`confirmRemove`
- `pages/memo.vue`：`submitMemo`、`toggleMemo`、`saveEdit`、`confirmRemove`、评论相关
- `pages/likes.vue`：`submit`、`flip`、`onDrop`、`confirmRemove`
- `pages/adore.vue`：`submit`、`saveEdit`、`confirmRemove`
- `pages/dislikes.vue`：`submit`、`saveEdit`、`confirmRemove`
- `pages/push.vue`：`submit`、`saveEdit`、`confirmRemove`
- `pages/letters.vue`：在编号 02 中处理

原则：

- **新增类**：成功后才清空输入框；失败保留内容。
- **勾选类**：失败时重新 `fetchAll()` 或重置 checkbox 的 `checked`，避免 UI 与数据库不一致。
- **删除类**：失败提示，不关闭确认后的界面状态。

### 4. 时间线删除确认

`components/TimelineCompact.vue` 增加：

```ts
function confirmRemove(id: string, title: string) {
  if (confirm(`删除节点「${title}」？`)) removeMilestone(id).catch(...)
}
```

## 验收标准

- [ ] 断网后发送留言：提示「发送失败」，输入内容仍在。
- [ ] 断网后勾选目标 / 备忘录：提示失败，勾选状态回滚。
- [ ] 断网后删除任意条目：提示失败，条目仍在。
- [ ] 时间线删除弹出确认；取消时不删除。
- [ ] 所有写操作失败都能在界面上看到原因，不再静默。
- [ ] 正常网络下功能行为与现在一致。

## 风险与回滚

- 改动机械但涉及文件多，需逐页回归。
- `alert()` 会阻塞操作，但项目现有风格如此；后续可替换为 Toast。
- 回滚：保留抛错、去掉页面的 try/catch 即可恢复旧行为。
