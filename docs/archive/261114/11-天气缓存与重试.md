# 11 · 天气缓存与重试

- 优先级：P2
- 类型：性能 / 隐私 / 体验
- 依赖：无
- 影响文件：`composables/useWeather.ts`、`pages/calendar.vue`

## 问题

1. 每次打开 `/calendar` 都会重新请求 `ipapi.co` 和 `open-meteo.com`。`ipapi.co` 匿名额度有限，频繁刷新容易失败。
2. 每次都会尝试浏览器定位，可能重复弹出授权；且把访问者 IP 发给第三方。
3. 失败时只有「天气获取失败（可能未允许定位）」，没有重试入口。

## 方案

### 1. 结果缓存

`useWeather` 使用 `sessionStorage`：

- key：`forus_weather_v1`
- 内容：`{ data, coords: { lat, lon }, city, at }`
- TTL：30 分钟

`fetchWeather(force = false)`：

1. 读取缓存；未过期且 `!force` → 直接赋值并返回，不发起任何网络请求。
2. 过期或无缓存：
   - 如果缓存里有坐标，直接复用，跳过 IP / 浏览器定位；
   - 否则先走 IP 定位；
   - 只有在 `navigator.permissions.query({ name: 'geolocation' })` 返回 `granted` 时才调用浏览器定位（避免重复弹窗）；
   - 请求 `open-meteo.com`；
3. 成功后写回缓存。
4. 失败时保留上一次的 `weather`（如果有），设置 `error`，用户可以重试。

所有 `sessionStorage` 读写包 `try/catch`，隐私模式下静默降级。

### 2. 暴露刷新

`useWeather` 额外返回 `refresh()`（等价于 `fetchWeather(true)`）。

`pages/calendar.vue` 的天气卡片：

- 在标题旁加一个很小的「刷新」按钮；
- 失败态显示「重试」按钮，点击调用 `refresh()`；
- 加载态保持现有「定位获取中…」。

### 3. 隐私说明

- 缓存命中时不会向 `ipapi.co` 暴露新的 IP；
- 首次定位仍会调用第三方，保持现状；
- 不引入新的天气服务。

## 验收标准

- [ ] 30 分钟内再次打开日历，Network 中没有 `ipapi.co` / `open-meteo.com` 请求。
- [ ] 点击「刷新」会强制重新获取。
- [ ] 已授权定位的设备不会每次打开都弹窗。
- [ ] 获取失败时显示重试入口，点击后能恢复。
- [ ] 清除 sessionStorage 后首次加载正常。
- [ ] 隐私模式下页面不报错（只是没有缓存）。

## 风险与回滚

- 30 分钟内天气可能不是最新；有手动刷新入口。
- `sessionStorage` 按标签页隔离，多标签会各自缓存。
- 回滚：移除缓存读写，恢复每次请求。
