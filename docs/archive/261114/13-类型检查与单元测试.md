# 13 · 类型检查与单元测试

- 优先级：P2
- 类型：工程质量
- 依赖：全部功能改动（建议最后执行）
- 影响文件：`package.json`、`package-lock.json`、新增 `vitest.config.ts`、`tests/*.test.ts`、`eslint.config.mjs`

## 问题

项目只有 `npm run build`，没有类型检查、Lint 或测试。`nuxt build` 不会严格检查 `.vue` 模板与 composable 的类型，认证、日期这类核心逻辑也没有回归保障。

## 方案

### 1. 增加依赖与脚本

```bash
npm i -D typescript vue-tsc vitest @nuxt/eslint eslint
```

`package.json`：

```json
{
  "scripts": {
    "build": "nuxt build",
    "dev": "nuxt dev",
    "preview": "nuxt preview",
    "typecheck": "nuxt typecheck",
    "test": "vitest run",
    "test:watch": "vitest",
    "lint": "eslint .",
    "lint:fix": "eslint . --fix"
  }
}
```

### 2. Vitest 配置

`vitest.config.ts`：

```ts
import { defineConfig } from 'vitest/config'
import { fileURLToPath } from 'node:url'

export default defineConfig({
  resolve: {
    alias: { '~': fileURLToPath(new URL('.', import.meta.url)) },
  },
  test: {
    environment: 'node',
    include: ['tests/**/*.test.ts'],
  },
})
```

### 3. 单元测试

`tests/token.test.ts`

- 正确 token 通过校验；
- 换密钥失败；
- 篡改 payload / 签名失败；
- 使用 `vi.useFakeTimers()` + `vi.setSystemTime()` 验证过期。

`tests/date.test.ts`

- `daysSince` 起始日返回 1；
- `togetherDuration` 起始日 `days === 1`（编号 08 修复后）；
- `nextAnniversary` 在周年之后自动滚到下一年；
- `todayCelebration` 命中周年、整百天；
- 使用固定 `now` 参数，避免依赖真实时间。

`tests/rate-limit.test.ts`（编号 07 完成后）

- 5 次失败后封锁；
- 封锁期间 `isBlocked` 返回 true；
- `clearFailures` 后恢复；
- 时间推进后自动解封。

测试只覆盖纯函数，不引入组件测试，保持轻量。

### 4. ESLint

运行 `npx nuxi module add eslint`，或手动添加 `@nuxt/eslint` 到 `nuxt.config.ts` 的 `modules`。

基线配置：

```js
// eslint.config.mjs
import withNuxt from './.nuxt/eslint.config.mjs'

export default withNuxt({
  rules: {
    // 纯风格规则可按需关闭，避免大面积格式化
    'vue/multi-word-component-names': 'off',
  },
})
```

原则：

- 修真实问题（未使用变量、错误的 `any`、潜在的 Vue 响应式问题）；
- 纯格式化规则如果产生大量无关 diff，可以关闭并记录；
- 不在本批次引入 Prettier 全量格式化。

### 5. 修复类型错误

`nuxt typecheck` 首次运行大概率会报错，逐项修复，重点：

- `marked.parse()` 的 `string | Promise<string>`；
- `useSupabaseClient()` 无数据库类型导致的隐式 `any`；
- `error.vue` 的 `NuxtError`；
- 实时频道变量 `any`；
- `useRequestFetch` 返回值。

不得用 `@ts-ignore` 大面积压制；确需忽略时写 `@ts-expect-error` 并注释原因。

## 验收标准

- [ ] `npm run typecheck` 通过。
- [ ] `npm run test` 通过，至少覆盖 token、日期、限流。
- [ ] `npm run lint` 通过（或只剩明确记录的可接受警告）。
- [ ] `npm run build` 通过。
- [ ] `package.json` / `package-lock.json` 已更新。
- [ ] 文档中的验证命令同步为 `build + typecheck + test + lint`。

## 风险与回滚

- 新增依赖会增大 `node_modules` 与安装时间。
- 类型检查可能暴露不少历史问题，修复工作量视报错数量而定。
- Lint 规则若过严可调整；不建议为了通过而大量禁用规则。
- 回滚：移除脚本与配置即可，不影响运行时。
