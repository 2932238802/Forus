# 07 · 解锁接口限流与恒定时间比较

- 优先级：P2（安全加固）
- 类型：安全 / 健壮性
- 依赖：无
- 影响文件：`server/api/unlock.post.ts`、新增 `server/utils/rate-limit.ts`、`server/utils/token.ts`（可选）

## 问题

1. `/api/unlock` 没有失败次数限制，可被脚本暴力枚举暗号。
2. 暗号比较使用 `!==`，签名比较使用普通字符串比较，理论上存在时序侧信道（低风险）。

## 方案

### 1. 新增内存限流器

`server/utils/rate-limit.ts`：

```ts
interface Bucket {
  failures: number
  windowStart: number
  blockedUntil: number
}

const buckets = new Map<string, Bucket>()
const WINDOW_MS = 15 * 60 * 1000
const BLOCK_MS = 15 * 60 * 1000
const MAX_FAILURES = 5

export function isBlocked(key: string): { blocked: boolean; retryAfter: number } { ... }
export function recordFailure(key: string): void { ... }
export function clearFailures(key: string): void { ... }
```

规则：

- 15 分钟窗口内最多 5 次失败；
- 超过后封锁 15 分钟；
- 成功解锁立即清空该 IP 记录；
- 每次调用顺带清理过期 bucket，`Map` 超过 10,000 条时移除最旧条目，避免内存泄漏。

### 2. 改造 `unlock.post.ts`

```ts
const ip = getRequestIP(event, { xForwardedFor: true }) || 'unknown'
const gate = isBlocked(ip)
if (gate.blocked) {
  setResponseStatus(event, 429)
  setHeader(event, 'Retry-After', String(gate.retryAfter))
  return { ok: false, error: '尝试过多，请稍后再试' }
}

if (!safeEqual(passphrase, String(config.passphrase))) {
  recordFailure(ip)
  setResponseStatus(event, 401)
  return { ok: false }
}

clearFailures(ip)
// 签发 Cookie
```

### 3. 恒定时间比较

在 `server/utils/safe-compare.ts`（或 `token.ts`）提供：

```ts
import { timingSafeEqual } from 'node:crypto'

export function safeEqual(a: string, b: string): boolean {
  const ab = Buffer.from(a)
  const bb = Buffer.from(b)
  return ab.length === bb.length && timingSafeEqual(ab, bb)
}
```

用于：

- 暗号比较；
- `verifyToken` 的签名比较（替换 `sig !== expected`）。

### 4. 限制说明

- 内存限流只在**单个 Nitro 实例**内有效。Vercel Serverless 多实例部署时，仍建议在平台 / 反向代理层再加一层全局限流（Cloudflare Rate Limiting、Nginx `limit_req` 等）。
- 不限制 `/api/status`、`/api/cat`，避免误伤正常使用。

## 验收标准

- [ ] 连续输入错误暗号 5 次后，第 6 次返回 429，并带 `Retry-After`。
- [ ] 封锁期间即使输入正确暗号也返回 429。
- [ ] 15 分钟后可重新尝试；成功解锁后失败计数清零。
- [ ] 正常一次输入正确暗号不受影响。
- [ ] 签名被篡改的 Cookie 仍然校验失败（`safeEqual` 行为不变）。
- [ ] 服务器内存中不会因大量不同 IP 无限增长。

## 风险与回滚

- 两个人在同一 NAT 后共用 IP；5 次失败/15 分钟的阈值足够宽松。
- 如果误锁，重启 Nitro 进程即可清空内存计数。
- 回滚：删除限流调用，保留恒定时间比较。
