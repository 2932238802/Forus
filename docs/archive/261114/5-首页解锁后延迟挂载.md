# 05 · 首页解锁后延迟挂载

- 优先级：P1
- 类型：安全 / 性能
- 依赖：无
- 影响文件：`pages/index.vue`

## 问题

`pages/index.vue:68` 的主界面容器始终渲染，只是用 `opacity-0` / 封面盖住。`NoteWall`、`MediaWall`、`CatChat` 在页面加载后立即挂载：

- 会向 Supabase 拉取留言、图片、小猫历史；
- 会建立 Realtime 订阅；
- 未解锁者的 DOM 里也能找到这些内容（虽然数据库本身对 anon 开放，但至少不应主动加载）。

封面没有真正阻止数据请求。

## 方案

只调整首页模板，不动 composable：

1. 保留封面逻辑与 `entered` 状态。
2. 将主界面（`NavBar`、`PokeAlert`、`CatChat`、宫格内容）整体包在 `<template v-if="entered">` 中。
3. 未解锁 / 状态未确认时不挂载任何数据组件。
4. 可选：在 `mounted === false` 时保留一个纯背景占位，避免首帧空白；不新增组件。

模板结构示意：

```vue
<CurtainIntro v-if="mounted && showCurtain" @opened="onOpened" />

<template v-if="entered">
  <NavBar />
  <PokeAlert :active="entered" />
  <CatChat />
  <!-- Celebration + 宫格 -->
</template>
```

注意：

- `entered` 在 `onOpened` 中同步置为 `true`，封面淡出期间内容开始挂载，数据在淡出 700ms 内加载，体验更好。
- 对已解锁的老设备，`refresh()` 完成后 `entered = true` 再挂载。
- `NavBar` 不依赖数据，但一起延迟挂载可以让未解锁页面更干净。

## 验收标准

- [ ] 未解锁停留在首页时，Network 中除 `/api/status` 外没有 Supabase REST/Realtime 请求。
- [ ] 未解锁时 DevTools 的 DOM 中不出现留言、图片、小猫对话节点。
- [ ] 输入暗号后，主界面正常出现，留言/图片/小猫正常工作。
- [ ] 已解锁设备刷新首页，直接进入且数据正常加载。
- [ ] 封面淡出过程无闪烁、无布局跳动。

## 风险与回滚

- 首次进入时内容出现会稍晚（等 `/api/status`），属于预期。
- 如出现闪烁，可给内容容器保留 `opacity` 过渡；回滚只需去掉 `v-if="entered"`。
